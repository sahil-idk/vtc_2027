DT-QUEST

A benchmark for digital-twin readiness in V2X datasets

Berlin V2X cellular data · Gate 1 cleaning · Gate 2 physics validation via Sionna RT

What we're building

Not a one-off cleaning of a single dataset — a reusable benchmark protocol for asking: "is this V2X dataset fit to build a reliable digital twin from?"

Gate 1 — readiness

Does the raw data itself hold up? Value correctness, representation, structure.

Gate 2 — fidelity

Does an independent physics reconstruction (Sionna RT) agree with what was measured?

The benchmark's real claim: a readiness signal computed without ever running Sionna should predict Gate-2 fidelity. That's what makes it a benchmark, not a checklist.

How Sionna RT works, concretely

A ray tracer needs an explicit 3D position for both ends of a link — this is physics, not a design choice.

Transmitterestimated tower position
→ LOS
→ reflection

Receiverreal vehicle GPS position
  • The scene: OSM building footprints, extruded to simple boxes with a concrete-like material model
  • For each valid path found, Sionna returns a complex amplitude + delay
  • Sum path power → one predicted received-power number per receiver, per tower
  • Compared against real measured RSRP, after a calibration step (Sionna's power isn't on an absolute dBm scale by default)

Transmitter() is the one call that needs a position the dataset never provides — that's exactly why the tower-estimation step exists, covered next.

How we estimate tower positions

The dataset never logs a tower's own position — only the vehicle's. So we estimate it directly from the data itself: Weighted Centroid Localization (WCL).

  • Every row connected to a given cell is a real GPS fix "near" that tower
  • Weight each fix by its linear signal power (stronger RSRP → closer to tower)
  • Take the weighted-average position across all fixes for that cell

Avoiding circularity

Each cell's rows are split into a disjoint localization set (60%, estimates the position) and validation set (40%, held out for Sionna comparison later) — never both from the same rows.

Consistency check

No independent ground truth exists, so we test physical plausibility instead: does RSRP get weaker with distance from the estimated position, as it should? Correlation more negative than −0.1 → high confidence; otherwise flagged low.

An asymmetry worth investigating

Op2 fails more than twice as often, at meaningfully longer range. Per the diagnostic's own logic: failures concentrated above the typical distance suggest a genuine scene-fidelity gap (worth --diffuse-reflection or higher --max-depth) rather than normal geometric noise — Op1's pattern (close-in, occasional) looks like noise; Op2's doesn't.

Op2 also hit a transient Overpass 504 timeout, recovered on retry — the retry logic worked, but this is also why Op2 fetched fewer buildings for a similar-sized area.
